# Viewer connection history

Viewer's connection form has a collapsed Recent Connections panel. It contains at most 20 most-recent distinct IP/port pairs, a checkbox to record authorized connections, and an explicit Clear button. Recording defaults on and its choice is remembered in the separate Viewer preferences. Startup selects the newest successful endpoint and fills IP/port, without connecting. An asynchronous history load does not replace an endpoint edited while loading or one already connecting. Disabling recording also disables automatic startup selection; Clear deletes the recent list. No credentials, certificate pins, invitation, optional permissions, clipboard, file names/content or input are stored in history.

Only a completed authenticated Host approval/attachment calls the recorder; failed/refused/pre-consent attempts do not. Both v2 and the old strict v1 connection path record after approval. The record does not mean an identity is trusted or that a physical desktop was verified. Selecting a record fills only IP and port, clears any current invitation/fingerprint/token and preserves the user's resource request settings. It does not connect or approve anything. Existing strict-pin mode remains selected and requires manually supplying the trusted pin again; history never downgrades that choice or restores a grant.

Normal current-user storage is `%LOCALAPPDATA%\RelaxDesk\preferences\connections.json`. The versioned JSON schema contains only `Format` and typed `Entries` with `Address`/`Port`. IPs are canonicalized, IPv6 is displayed in brackets, duplicates move to the front, and old entries are pruned at 20. Documents above 16 KiB, extra or duplicate properties, invalid/null entries, non-IP hosts and invalid ports are rejected. Unknown/corrupt content is preserved until explicit Clear, rather than overwritten by a successful connection.

File operations run off the Dispatcher and network workers, serialized within the Viewer store instance. Replacement uses a random temporary file in the same directory and an atomic rename; cancellation is checked before commit and temporary files are cleaned. Preflight refuses reparse ancestors/files and directory collisions. This is ordinary current-user preferences, not a race-proof privileged data store: concurrent separate Viewer processes may overwrite each other's recent-list update. It holds no secrets or identity trust. Filesystem redirection/races, arbitrary kernel IO hangs and power failure are not claimed transactional. History IO failure updates the history notice and leaves an authorized screen session running.

Automation commands disable real-user persistence. The dedicated WPF history test injects a repository fixture store and uses a real Host/TLS with synthetic video; other verification/smoke launches never load or save the actual preference file. [Evidence](../benchmarks/2026-11-24-connection-history-validation.md) covers schema/privacy, real file/junction handling, actual WPF selection/save/clear and locked-file isolation. Final unified bundle/Home acceptance remains deferred; no package was generated.


Saved login credentials are a separate opt-in Windows Credential Manager entry,
not part of the history JSON. Selecting an endpoint may autofill that separate
entry after temporary secrets have been cleared. See [Viewer UI](VIEWER-UI.md).
