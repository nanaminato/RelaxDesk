## Delivery exit gates

1. Close mandatory **source** gaps and build changed projects; retain focused checks and first failures. A missing new artifacts-directory restore was corrected during the toolbar check; the subsequent build is warning/error free.
2. Reconcile the end-user guide with current features. Include tracked `docs/` and `benchmarks/` in the final package, preserving dates and limitations; never sweep build fixtures, application logs, credentials or private screenshots into it.
3. Commit the source and guide, then create **one** final self-contained win-x64 bundle. Verify manifest, version/native notices and the actual packaged office suite; preserve every failing/unrun result. A package created from dirty source must identify that honestly, not imply the commit alone describes it.
4. Deliver paths/hash, modules, protocol changes, exact automated results and the operator checklist. Owner performs the deferred Home dual-PC/installation/hardware/office tests. Do not mark them passed or the overall physical exit complete from software fixtures.

The current Windows Server/RDP runner cannot certify the physical gates above. This does not block source fixes, reproducible scripts, documentation or final package validation. It does prevent a truthful claim that the complete physical-office milestone is accepted.
