# 认证、设备信任与会话接管

## 首次连接与信任

Viewer 先验证 Host TLS 身份，再提供账号密码和设备私钥证明。首次连接须核对证书指纹，并由 Host 本机批准设备。保存的指纹不匹配时应停止并核实原因，不应自动接受新证书。

被批准的设备凭有效密码可再次连接；保存密码不等于永久授权。Host 可在受信任设备中撤销，撤销会结束该设备的活动连接。修改登录信息前先停止共享；修改密码会清除原设备授权。

Host 的“断开本次连接”结束当前会话，“停止共享”关闭监听。授权连接中的剪贴板、文件和声音按协商能力工作，不重复要求逐项批准。

## Host 正忙时

Host 同时只有一个控制会话。受信任设备连接到忙碌 Host 时，Viewer 需明确选择接管；取消或超时不替换当前控制端。首次设备在 Host 忙时不能直接踢下当前会话。

确认后，旧会话终止并清理输入，新会话才取得控制。旧 Viewer 收到有效接管通知后不应自动抢回。终止通知丢失时可能只显示传输错误，不能只根据错误文案判断是否已完成接管。

## 安全边界

控制和资源通道均需认证及加密，不提供无鉴权输入接口。Host 对登录尝试、密码验证和接管请求设有界限及退避，但这不是公网 DDoS 防护。

优先通过可信 LAN 或虚拟组网访问；公网部署见[异地访问指南](REMOTE-ACCESS.zh-CN.md)。不要关闭 UAC、改变 Windows RDP 组件或把安装服务视作安全桌面访问授权。
