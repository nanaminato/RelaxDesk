# 连接防爆破与单会话接管

## 使用方式

- 新设备必须先验证 Host 的 TLS 身份，再通过账号密码和设备私钥验证；首次连接仍由 Host 本机批准。未受信任的设备在 Host 忙时只能重试，不会打断当前会话或弹出第二个 Host 审批框。
- 已受信任的设备主动连接时，如果已有会话，Viewer 会显示「继续将断开当前控制端」。选择「接管连接」可替换当前连接，不需要旧 Viewer 同意；取消或在确认期限内未响应不会断开旧 Viewer。
- 接管后，旧 Viewer 收到明确的会话终止原因，不自动抢回。即使终止通知丢失，自动重连请求也不会收到接管确认。Host 本机仍可停止共享及撤销信任。
- 请优先配对更新 Host 与 Viewer。旧 v5 Viewer 可按原流程连接空闲 Host，但不协商新接管；新 Viewer 对旧 v5 Host 也不会自行接管。更旧的协议版本仍按原规则拒绝。

## Host 安全边界

Host 在共享期间保留同一个有界 TLS 入口。普通登录单独处理；已授权会话的 TCP 视频、文件、剪贴板和音频接入必须匹配其各自的一次性票据和消息类型，不能被另一个登录占用。QUIC 附属通道继续用原有独立安全绑定。过载时未验证的 TCP 请求可能被直接关闭，不暴露当前会话状态。

Host 发起带随机挑战的设备证明；身份是验证过的公钥指纹，不是客户端自报的名称。成功验证密码且本机信任有效时，可为该指纹签发 30 日设备凭证，Viewer 缓存在当前 Windows 用户下。返回时仍做新挑战、密码校验及本机信任检查；从旧版升级或凭证过期的真实设备可续签。凭证独自不能进入或取得接管权。撤销通过本地控制通道先阻断新的接管决定，再移除持久信任；账号密码修改仍要求先停用共享并清除已信任设备。

固定窗口限频全部在内存中：

| 操作 | 每分钟预算 |
| --- | --- |
| TLS 入口 | 来源 60、全局 480；最多 16 条并行受理 |
| 登录请求 | 来源 20、全局 120，先于设备挑战 |
| 密码校验 | 来源 10、经证明设备 6、全局 60；最多 2 次并行密码计算 |
| 凭证签发 | 来源 6、设备 2、全局 24 |

IPv6 按 /64 归并来源，IPv4 映射地址计入相同 IPv4 来源。连续失败从第三次开始有 2/4/8/16 秒渐进冷却，到窗口终点恢复；没有永久锁定。成功可清除该设备的失败冷却，但不能清除共享 IP 的计数或硬窗口。有效长度内的未知账户和错密码均经过相同的密码派生并返回同一拒绝状态。握手和计数内存都设上限；这些措施不是公网 DDoS 防护。

接管确认只在当前已认证的 TLS 连接上可用，票据 30 秒有效且一次性。确认必须对应当时那条仍在控制中的会话。Host 串行保留一个继任名额，取消旧会话、撤销权限、等组件停止及键鼠释放后，才让新会话取得输入。旧会话尚在审批、正在初始化或已经换人时，不接受旧确认。若发现旧键鼠清理失败，Host 拒绝继续接管，需本机检查键鼠并重启共享。没有自动排队或无确认抢占。

## 验收

2026-11-28 已完成 Android / Windows 双向实际 LAN 接管：两个方向各两次确认接管，旧端退出且不自动抢回，新端实际桌面和基本鼠标/键盘输入通过；确认超时不打断旧端。Android 一次将接管退出显示为 EOF，另一次显示正常终止提示，原因呈现竞态仍待修复。未扩大为按住键鼠释放、同时竞争、撤销竞态或性能验收。

后续已 修复 Android EOF 原因竞态：传输失败后为已认证控制通道保留 300ms 有界收尾窗口；明确通知优先，缺失/畸形通知不伪造原因。8 项终止检查及实际 TLS 先后顺序回归通过，并在实际 Host 接管修复版时复核退出提示。

- RelaxDesk.Tests 覆盖有界计数、并行窗口、签名身份与到期、附件票据路由、并行/陈旧接管、清理失败不授权及真实回环 TLS 上的 Viewer 确认/取消/自动重连拒绝协议。
- Windows 物理验收使用匹配的 Host、Viewer 和第二台 Viewer（两套不同设备密钥），先批准两台。A 控制时让 B 输错密码、取消接管、或在对话框超时，确认 A 不受影响。再确认接管，验证 A 的终止原因、按住的键鼠释放、B 的画面/输入、A 不自动抢回。两个候选同时确认只允许一个成功。另测陌生设备、在 B 等待确认时从本机撤销 B、以及 A 正在建立附属通道时的额外登录。使用空白编辑器和测试文件，不使用真实用户内容。
