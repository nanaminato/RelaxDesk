# Viewer pointer presentation

The Viewer draws the DXGI pointer only while the local cursor is over actual remote desktop pixels in the foreground Viewer. Leaving the video, entering letterbox/pan controls, switching applications or entering an overlapping local window hides the remote pointer. The fullscreen connection bar, its collapsed edge strip and its open menu are local UI and suppress the remote pointer. Their normal local cursors remain available. No host cursor visibility or input authorization is changed.

Native HWND move/leave tracking and WPF enter/leave/activation events update the presentation immediately. The existing 100 ms connection-bar poll also reconciles stationary-cursor changes such as a newly opened overlay. No additional polling timer or network message is introduced. GPU drawing reads a volatile presentation flag and repaints the retained GPU frame via the existing signal; hiding its separately drawn pointer does not require a new desktop frame, keyframe, GPU readback or decoder reset. CPU drawing retains cursor-free decoded pixels and reuses one scratch array for compositing, so hiding/re-entry cannot burn a cursor into the retained image. Cursor presentation changes do not increment received-frame statistics.

GDI compatibility capture now excludes its baked cursor and uses the local arrow. This path does not mirror remote cursor shapes or remote application cursor hiding; DXGI retains remote pointer shapes/visibility. Older Hosts that bake a cursor into image pixels cannot have that cursor erased by a new Viewer, so update both endpoints for GDI. Protocol framing and grants remain unchanged.

Microsoft's [RDP cursor channel overview](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-rdpemsc/5994460f-3880-4eef-b385-dd4b4b9b4b93) documents independent cursor shape/position delivery, and [mouse tracking guidance](https://learn.microsoft.com/en-us/windows/win32/learnwin32/other-mouse-operations) documents leave tracking. These support the design; they do not establish every MSTSC client version's exact leave/toolbar behavior. This is analogous Viewer behavior, not an RDP implementation.

## Validation

Run `dotnet src/RelaxDesk.Viewer/bin/Release/net11.0-windows/RelaxDesk.Viewer.dll --pointer-contracts` after a Release build. It verifies CPU pixels remain unchanged, static hide/re-entry without trails, foreground/window/letterbox policy, native mouse leave notification, fullscreen bar/menu suppression, re-entry and disconnect. Test points are simulated without desktop cursor injection. The case is included in the shared office acceptance list. Existing `--toolbar-contracts` covers native input exclusion/release and bar lifecycle.

Manual dual-machine checks remain: actual hover across all four video boundaries, black bars at different zoom/pan settings, fullscreen strip/expanded buttons/open menu, dragging across the strip, Alt-Tab/minimize, idle desktop, CPU fallback, GDI arrow and remote text/resize/hidden cursor shapes under DXGI. Check mixed DPI monitors and verify entering local UI cannot send button actions to the Host. Do not infer physical input-to-photon latency from these contracts.
