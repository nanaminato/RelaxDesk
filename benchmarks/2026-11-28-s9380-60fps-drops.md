# Android LAN 真机性能与丢帧对照

日期：2026-11-28。本次测试观察到缓冲队列调整后额外丢帧减少，但没有达到稳定 60 FPS。结果仅适用于下述设备和测试版本。

## 测试条件

- Viewer：Samsung SM-S9380，Android 16 / API 36，SM8750，原生硬件解码器 `c2.qti.avc.decoder`，日志确认低延迟模式启用。
- Host：Windows 物理桌面，Desktop Duplication，2560×1440 SDR，Intel Quick Sync 硬件 H.264。
- 网络：直接 Wi-Fi LAN，TCP/TLS；没有注入延迟、丢包或带宽限制。无线重传和独立链路容量未测。
- 视频设置：手动 60 FPS / 12 Mbps，自动画质关闭。目标值不代表实际交付帧率或吞吐。
- Host 测试版本：`0.4.2-localtest.20261128.gf00a9ad.worktree`，各组使用同一 Host 进程和 native DLL。Android 为队列优化前后的独立 ARM64 Release 测试包，包含相同的阶段统计；不是两个正式发布版本的比较。
- 负载：同一全屏细线和运动矩形动画。各组从头运行，持续运动期间采样，启动相位未逐帧锁定。ADB 稀疏日志采集同样使用 Wi-Fi。

## 两轮对照结果

A 使用两帧压缩队列；B 使用六帧队列和 50 ms 驻留期限。超时或超容量时丢弃依赖链并请求关键帧，避免无限积压。

顺序为 A1 → B1 → A2 → B2。每组采集约 85 秒、约五秒一次；跳过前两次样本，取十二个计数间隔，约 60 秒。FPS 由 Android 同一单调时钟的累计计数差计算。输出指解码后向 Surface 释放输出，不代表物理面板扫描完成。

| 组别 | 区间 s | 收到 / 输出帧 | 接收 FPS | 输出 FPS | 已知新增丢帧 | 丢帧 / 接收 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| A1 | 60.042 | 2494 / 1890 | 41.54 | 31.48 | 603 | 24.18% |
| B1 | 60.014 | 2381 / 2346 | 39.67 | 39.09 | 36 | 1.51% |
| A2 | 60.028 | 2534 / 2487 | 42.21 | 41.43 | 48 | 1.89% |
| B2 | 60.014 | 2612 / 2593 | 43.52 | 43.21 | 21 | 0.80% |

两轮均观察到输出增加、额外丢帧减少，但第二次基线本身已明显改善；不能将首轮改善当作固定收益。没有置信区间或受控无线重放。丢帧比例是已知 Viewer 丢帧，不是网络丢包率。

## 瓶颈与延迟边界

稳定窗口末尾，Host 编码 P50 约 19.95–20.40 ms，采集 P50 约 1.53–1.83 ms，源帧间隔 P50 约 22.15–22.25 ms，无法持续提供 16.67 ms 一帧的 60 FPS。编码计时包含 GPU 转换、同步及 MFT 等待，不能当作纯硬件编码核时间，也不能把重叠阶段相加。

手机收到至提交 P95：A1 3.88 ms、B1 3.80 ms、A2 4.05 ms、B2 4.00 ms。B1 队列峰值为六、B2 为五，稳定窗口内未触发期限丢弃。这些阶段分位数来自窗口末尾最近最多 1024 个样本，不是完整六十秒分位数。

各组手机解码调用 P95 为 0.89–0.98 ms，输入缓冲等待和 Codec 故障恢复均为零；提交至输出释放 P50 约 12.22–12.61 ms，属于异步流水线延迟。Host 发送背压与到帧突发也有记录，尚未通过抓包拆分 Wi-Fi、TCP 和接收调度各自的贡献。这些观察不保证其他设备没有解码瓶颈。

未测：物理 input-to-photon、真实屏幕扫描显示、长时热稳定、4K、多 GPU 兼容矩阵和同条件 MSTSC 对照。动画结果不代表全部办公负载。

## 如何复测

使用同一 Host、相同显示设置、相同负载和真实认证/本机批准流程。保存带版本信息的基线包和优化包，交替测试，保留预热后的完整计数窗口以及失败样本。

Android 阶段统计由 `RelaxDeskPipeline` 日志提供；采集四组日志后可用仓库脚本汇总：

```powershell
python scripts/summarize-android-pipeline.py <A1.log> <B1.log> <A2.log> <B2.log> --output <comparison.json>
```

原测量日志位于测试机器的本地 `out/android-validation/`，未随仓库提供；汇总工具不会自动重建动画、安装基线包或复现无线环境。报告保留观察值，独立验证需要重新采集。通用采集方法见[测试指南](../docs/BENCHMARK-COLLECTION.md)。
