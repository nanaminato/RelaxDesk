# Android / Windows 双向接管实机验证

日期：2026-11-28。使用现有已受信任设备及保存的凭据，连接同一实际 LAN Host；没有使用合成 Host，没有改动密码/信任/Windows 策略，没有部署新的 Host 或 Viewer。

环境：Host `192.168.1.2:48200`，版本 `0.4.2-roles.20261128-000247.g810b20d`；Windows Viewer `0.4.2-roles.20261128-004750.g8f7e10e`，开发机 `192.168.1.3`；Samsung SM-X510 Android 使用前轮已安装的修复版 Debug APK。远端桌面 2560×1440，Android 解码器 `c2.exynos.h264.decoder`。未收集密码、密钥或票据；Android 保留安全窗口标志，没有绕过禁止截屏策略。

## Windows 接管 Android

1. 初始 Android 正在接收真实桌面，显示有效 RTT 和解码统计。Windows 主动连接后收到“继续将断开当前控制端”的确认。
2. 首次对话框在 UI 自动化定位期间超时，Windows 显示“已取消接管”，Android 心跳继续、会话未退出，验证超时不抢占。
3. 再次发起并明确确认，Android 退出回连接表单，Windows 新端显示实际远端桌面，工具栏报告硬件编码/GPU 显示。
4. Windows 远端鼠标输入将 Host 窗口从约 `(858,342)` 拖到 `(938,382)`；桌面右键菜单实际出现，再用键盘 Escape 关闭，画面反映操作结果。没有点击设置或执行命令。
5. Android 旧端约 80 秒内未自动抢回，直到本轮手动发起反向接管。

结果：接管、旧端退出、新端画面与鼠标/键盘基本输入通过。首轮 Android 旧端显示 `EndOfStreamException`，没有正确呈现接管原因；这是退出提示/并发收尾问题，不应写为提示验收通过。

## Android 接管 Windows

1. Android 主动连接，明确显示“继续将断开当前控制端。是否接管这台电脑？”，确认后 Windows 退出全屏回到连接表单，显示“会话已被另一台设备接管”。
2. Android 新端显示 2560×1440 解码统计、有效 RTT，退出连接表单并进入会话工具栏。不是仅以登录成功判断收到画面。
3. Android 视频 Surface 为 `[0,72]–[2304,1368]`，直触模式将远端 Host 窗口拖回原位置。随后通过 Android 硬件按键路径发送 Alt+Space。
4. 为独立核对实际输入结果，再由 Windows 明确接管观察：窗口已回到约 `(858,342)`，远端注册 Alt+Space 的快捷启动面板已打开。此状态产生于 Android 控制期间，Windows 新连接观察前未发送远端输入，证明 Android 鼠标与键盘均实际生效。没有输入或执行任何启动命令；随后关闭面板，恢复桌面。
5. Windows 旧端约 80 秒内未自动抢回，直到本轮手动发起下一次连接。

结果：接管、旧端明确退出、新端媒体及鼠标/键盘基本输入通过。

## 重复接管与最终状态

本轮共确认四次实际接管，两个方向各两次，另有一次确认超时取消。第二次 Android 被替换时正确显示“远程会话已结束或已由其他设备接管”，与第一次 EOF 提示不同，说明原因呈现有竞态。没有修改产品代码掩盖此问题。

最后由 Android 再次明确接管，恢复开始验证时的控制端；Windows 留在已被接管的连接表单，Android 保持实际会话。远端窗口位置、临时菜单/启动面板已恢复，没有创建或修改远端文件。

证据来源：Windows Viewer 实际窗口截图和可访问状态、Windows `viewer.log`；Android UI 层次、实际解码 HUD 和应用日志。Windows 日志记录 `RemoteSessionEndedException`；Android 初轮退出为 EOF。两端时钟未同步，不用这些时间差计算接管延迟。

未覆盖：长时间压力、同时竞争、错误密码/陌生设备/撤销竞态、接管时按住修饰键或鼠标的物理释放、文字/IME/滚轮、多显示器切换、UAC/锁屏、帧率/带宽/输入到上屏基准。此次只新增验证文档，没有产品代码变更，未为文档重跑单元测试；不将此前契约测试计为本轮新测试。
